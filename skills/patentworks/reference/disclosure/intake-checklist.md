# 交底書 Intake 問題集(引導發明人)

> 用來把發明人腦中的東西結構化擷取。不必逐題照問,缺什麼補什麼;目標是湊齊 drafting 與 claims 所需的素材。

## 1. 背景與問題
- 這個發明要解決**什麼具體技術問題**?(不是商業問題)
- 現有的人/產品**怎麼做**?(最接近的現有方案是什麼)
- 現有做法的**痛點/技術缺陷**是什麼?(要是技術性的:效率低、誤判、耗能、不穩…)

## 2. 技術方案(核心)
- 你的**核心構思**一句話是什麼?
- 由哪些**關鍵步驟 / 組件 / 模組**構成?各自做什麼?
- 它們**怎麼串起來運作**?(資料/訊號/物料怎麼流)
- 用到什麼**原理 / 演算法 / 結構 / 材料 / 參數**?

## 3. 必要技術特徵(claims 種子)
- 哪些特徵是**達成效果不可缺少**的?(缺了就不work或回到現有技術)
- 哪些是**錦上添花/可選**的?(→ 從屬項素材)

## 4. 區別與創新點
- 跟最接近的現有方案,**差在哪一步/哪個特徵**?
- 這個差異**為什麼能解決上面的問題**?
- 列出**擬保護的創新點**(可多個;標出彼此是否屬同一發明構思)。

## 5. 有益效果
- 帶來什麼好處?**能否量化**?(數據、實驗條件、對比基準)
- 跟現有方案比的**具體改善幅度**?

## 6. 實施例與變化例
- 有**幾種實作方式**?(不同實施例越多,保護越寬)
- 關鍵**參數的範圍**(上限/下限/代表值)?
- 換一種材料/演算法/參數會怎樣?(→ 變化例)

## 7. 圖
- 需要哪些圖:**系統架構圖 / 方法流程圖 / 時序圖 / 結構示意圖 / 資料結構**?
- 各圖的主要組件與編號?

## 8. 行政
- 發明名稱(初擬)、技術領域、應用場景。
- 發明人、權利歸屬、是否已對外公開(影響新穎性與優惠期)。
- 目標法域(共通/TW/CN/US/EP)→ 決定後續 drafting 載哪份法域知識。
