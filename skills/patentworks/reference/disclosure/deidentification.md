# 脱敏檢查表(交外部代理人前必做)

> 技術交底書常含內部敏感資訊。送出給外部專利代理人或上傳外部服務前,逐項清掉;**保留技術實質,抽象化具體標識**。

## 必移除 / 代換
- **客戶 / 公司 / 部門名稱** → 改「某客戶」「本公司」或角色化描述。
- **產品名 / 商標 / 型號 / 專案代號** → 改通用技術名稱(商標型號本來就不該進說明書,見 drafting common.md §3)。
- **人名**(發明人除外的內部人員)、聯絡資訊。
- **內部系統名 / 伺服器 / 路徑 / 網域 / IP / 帳號**。
- **商業數據**(營收、報價、成本、客戶數)、**未公開的合作方 / 供應商**。
- **可定位的具體場域**(特定廠房、產線、地址)→ 抽象成「某生產環境」。
- **程式碼中的密鑰 / token / 憑證 / 連線字串**(若引用 code 片段)。

## 抽象化原則
- 把「某客戶的 X 系統」改寫成「一種 X 系統」——技術方案不變,標識消失。
- 具體數值若屬機密但對技術必要,改成**範圍或代表值**並說明依據(不是刪掉)。

## 保留(不可脱敏掉)
- 技術問題、方案、必要技術特徵、效果、實施例參數——這些是專利的實質,不能因脱敏而損及充分公開。

## 自檢
- 全文搜一遍敏感關鍵字(公司名/商標/代號)確認無殘留。
- 脱敏後再讀一次:技術方案是否仍**完整、可據以實現**?
